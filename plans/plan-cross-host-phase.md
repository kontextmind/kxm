# KXM cross-host phase: revised delivery plan (post-S5)

Proposed slice edits for Tracking. This document schedules nothing by itself: accepted slices, owners and status land in `plans/implementation-plan.md` under **Still open → The one queue**, and this file is a design record once they do. Baseline read: `df878d6` (S5 edge deployed, `studio.kxmd.dev`, interactive browser click-through open).

## A. Governing rulings carried forward

Every slice below obeys these. A slice that needs one relaxed is not in this queue; it needs a new written decision first.

1. **One tracker.** Tracking owns execution order. This plan proposes P0–P6; no second backlog, no catalogue numbering.
2. **Tenancy is the machine.** One tenant = one box = one hub, a tenant *label* and no tenant table. Every VM running KXM is its own box with its own hub, Runtime, state set and Studio (operator, 2026-09-22). Cross-host in this phase means **boxes inside one tenant, plus the operator's laptop**. Nothing here lets one tenant's box reach another tenant's hub.
3. **The hub binds loopback and interprets no browser identity.** `isLoopback(host) || KXM_AUTH_TOKEN` stays the only listener rule; the hosting recipe pins `KXM_HOST=127.0.0.1`; the proxy keeps `/v1/*` and the supervisor off every public interface. No slice changes the bind. A cross-box surface is a **machine client with existing credential shapes** (admin bearer, `KXM_PROJECT_TOKENS`, the persisted hub env record, `kxm hub bind` refusing a remote URL without a resolvable credential) or it does not ship.
4. **No PostgreSQL write path.** SQLite stays authoritative per box. Tables added here are SQLite tables in the hub store or the event store, each stated per slice and gated in the same change. The disposable per-hub reporting projection keeps its existing trigger.
5. **A2A Protocol is a projection, never the transport.** No Agent Card, binding, push surface or task-state wire format ships. A2A vocabulary may be borrowed for names only.
6. **`kxm peer` is the live transport.** `send`, `get`, `await`, `fanout`, `cancel`, `inbox`, `reply`, `list` over the hub HTTP API with bearer tokens remain the only agent-to-agent path. Slices extend those verbs and endpoints; no parallel transport ships beside them. The Runtime→hub sync-event outbox (P5) carries run lifecycle facts, not agent messages, and is the Phase 2/8 outbox the contracts already name.
7. **Run ownership and execution stay put.** `homeRuntimeId` is immutable; stages run only on the owning box's CPU; a remote box takes part as an online peer and by owning its own runs. Different box = message plus checkpoint plus signal. Phase 6 (remote execution) is not passed by reaching a box, and nothing here claims it.
8. **The supervisor is never reachable across hosts.** Its boundary is a `0600` token file plus HMAC on loopback. The Runtime dials the hub; the hub never dials the Runtime.
9. **Memory never grants tools, secrets, approvals or policy.** Messages are data, never consent. A message body can never change roster, policy, ceilings or leases; the intake ceiling may never widen under rebind (already pinned).
10. **Gates as code, not memory.** Every loop this phase adds is held by a failing named test or a workflow `gate` step. Nothing is enforced by AGENTS prose or by asking a model to remember.
11. **Single operator: no migrations.** A schema bump refuses an older database with `runtime_schema_outdated`; the operator deletes and re-inits. Each bump moves the backup/restore ceiling in `database.ts` in the same change, updates the table pin, and re-runs the deployed restore witness before the next slice starts.
12. **Verify gate unchanged.** Existing `npm run verify` and the existing CI legs. At most one focused named test per slice inside an existing suite. No new npm script, CI job, platform leg, broad test file or coverage ratchet.
13. **Sync is allowlist-first.** Anything that leaves a box is a schema-declared, pre-redacted `kxm.sync-event.v1` or an existing peer message record. The hub accepts an exact event once by `{projectId, runId, sequence}`; conflicting reuse is a security alert; projections never invent events.
14. **Unknown side effects are never replayed.** They enter `blocked_uncertain` and wait for a human or a deterministic probe. A lost lease never triggers a retry.
15. **Recorded gaps stay recorded.** `producerPolicy.acceptedStatuses` is not consulted at settlement; that trigger (first workflow gating acceptance on peer review) is untouched here. No slice changes fold rules or evidence semantics.

**One stated assumption that shapes P0.** A machine client on box B reaches hub A's loopback listener over a substrate the **operator owns**: an SSH local forward with a pinned host key (KXM's own SSH module already rejects TOFU; a plain `ssh -L` must use `StrictHostKeyChecking=yes` with a known-hosts entry) or a private overlay address. KXM ships no tunnel manager in this phase. To KXM the result is nothing more than a remote hub URL and a resolvable project token, which is exactly what `kxm hub bind` already accepts and labels `remote`. If P0's witness shows this substrate is unworkable for tenant VMs, the queue stops at P0 and the substrate becomes its own decision.

## D. Risks and invariants

Each line names what could silently break and the gate that holds it.

| Invariant | How it breaks silently | Gate |
|---|---|---|
| **Schema honesty.** An older store never runs against newer code, and a newer store never opens under older code | a version bump without the DDL underneath, or a table pin left stale, shows up later as a query against missing columns | per bump: `HUB_STORE_TABLES` / event-store table pins, `store rejects databases created by a newer schema`, `runtime_schema_outdated` on older files, restore ceiling moved in `database.ts` in the same change, deployed restore witness re-run before the next slice |
| **Backup unit is the state set.** A v3 hub backup cannot restore into a v4 hub | the operator restores an old snapshot and the hub reports healthy with the wrong schema | restore ceiling refuses; the operations backup section names the re-init and re-backup step after every bump |
| **Hub loopback.** The hub never gains a non-loopback listener and `/v1/*` never reaches a public interface | a "helpful" bind change or a proxy directive that forwards `/v1/*` | `KXM_AUTH_TOKEN is required when binding beyond localhost` brake, `KXM_HOST=127.0.0.1` in the recipe, `hub bind refuses a remote hub with no credential and labels the binding scope`, S5 edge re-check recorded in P0 and after P5 |
| **Substrate is operator-owned and pinned.** A forward to loopback with a pinned host key, never a bind | a TOFU forward or an unpinned overlay lets an on-path host present as the hub | strict host-key policy in KXM's SSH module; the operations invariant for plain forwards; P0 witness records the pinned key |
| **Tenant boundary.** No box binds another tenant's hub | a tenant token copied to the wrong VM | tokens are per tenant hub and per project; the portal's tenant→endpoint map is the only cross-tenant list; documented refusal to bind across tenants |
| **Presence is hub-clocked.** `online`, `stale`, `offline`, `leaseExpiresAt` derive from the hub clock and heartbeats, never client timestamps | a skewed client makes a dead agent look alive, or a queued message never expires | P1 test, `stale agents are marked offline and logged`, P2 and P3 tests use an injected hub clock, never elapsed-time guesses |
| **Delivery is once per message id.** Reconnect redelivers only rows past the consumer cursor; ack advances it | duplicate delivery on flapping connections, or a message lost before ack | P2 test, `idempotency keys deduplicate exact retries and reject conflicting reuse`, `message acknowledgement, visibility, reply, and terminal-state authorization are enforced` |
| **Settlement semantics unchanged.** Queued or offline-delivered messages become evidence only through hub-authorized `workflowContext`; leases never alter fold rules; `acceptedStatuses` stays a recorded gap | a cross-box reply reads as a passing checkpoint because it arrived through a new path | `verified peer evidence survives restart and source-message retention without a schema bump`, workflow-quorum and driver suites unchanged; every PR in this phase states "no fold rule or evidence rule touched" |
| **Fencing is the hub's, and the loser parks.** One lease writer, CAS in one transaction, monotonic token, expiry by hub clock; a superseded token at commit leaves the effect uncertain | two boxes push to the same ref, or a stale holder's late commit lands | P3 test, external-effects Q6 heartbeat tests, `blocked_uncertain` recovery path from D4 |
| **No auto-retry after a lost lease** | a retry loop re-executes a push whose outcome is unknown | `blocked_uncertain` is the only landing state; `recoverKxmRun` needs a human or a deterministic probe |
| **Credentials stay on their box.** The remote project token lives in the client box's env; the binding record stores no secret; sync events carry status only | a token written into `hub-binding.json`, a sync event or a log line | hub-binding tests, `structured logs never include prompt or reply bodies`, redactor registration in the P5 transform, `kxm.sync-event.v1` `additionalProperties: false` |
| **Allowlist before outbox.** No local event is placed in the outbox; only the derived sync object | a "temporary" passthrough field | contract test on `schemas/sync-event.schema.json`, P5 test asserting bounded fields only |
| **Exact-once sync by sequence.** Same bytes idempotent; different bytes under a used sequence refused and alerted; gaps pending, never invented | a re-pushed outbox after restore renumbers and overwrites | P5 test, hub `sync_events` unique index, P4b durable sequence for intake |
| **Supervisor never on the network.** P4c and P5 are outbound pulls and pushes from the Runtime | a hub→Runtime callback added for latency | `supervisor API misuse` test, recipe invariant; any such endpoint fails review |
| **Rate limits and hops apply to remote agents.** Per-agent buckets, fanout ≤3, hop ceilings unchanged | a remote peer loops through queued delivery | `rate limiting returns retry guidance and resets after the window`, `message fields, delivery modes, hop limits, TTLs, and target rules are validated` |
| **Portal path untouched.** S2/S4 `qm guest exec` reads and simulated drives are not a courier | the portal grows a "forward this message" endpoint | per-tenant hosting exclusion list; no portal change in this queue |
| **Timing flake class does not return.** No slice widens a timeout | a presence or lease test that passes alone and fails under load | injectable clock or real barrier only (Still open rule); a lone red in these names is re-run through `npm test` and said so in the PR |
| **One test per slice, existing suites.** | coverage grows by test files instead of by behaviour | Cross-cutting test gates text; reviewer refuses a new suite |

**What this phase does not claim.** Phase 6 (remote execution), Phase 11 (isolation, takeover), the interactive S5 login witness, and any Phase 8 PASS before P6. A box being reachable proves reachability, not a gate.
