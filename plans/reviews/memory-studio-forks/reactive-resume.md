# Reactive Resume → KXM Studio: editor architecture audit

## Scope and disposition

**Category:** structured document editor and publishing application. **Applicability:** high for Studio authoring, moderate for review/export, low for agent execution. **Disposition:** adapt selected interaction and module boundaries; defer incorporating the application or its service stack. This is a separate, source-only review of `kontextmind/reactive-resume` at `fd3494ccac6ef4c47d01614a8a5dcdea08df85eb`, compared with KXM at `02aaed31fd6160a78378c677ab27d4119f039621`. No upstream installation, execution, account access, or runtime validation occurred. “Implemented” below means visible in inspected code, not demonstrated in a deployed system.

The useful artifact is an editor surrounding a canonical document, not a replacement KXM agent engine. Its private Node ≥24/pnpm/Turborepo workspace separates web, server, and reusable packages. KXM already exposes core, runtime, client, extension, and MCP entry points from one npm package; Studio should remain another client of that installation. [Upstream workspace](https://github.com/kontextmind/reactive-resume/blob/fd3494ccac6ef4c47d01614a8a5dcdea08df85eb/package.json#L1-L46), [KXM package boundaries](https://github.com/kontextmind/kxm/blob/02aaed31fd6160a78378c677ab27d4119f039621/package.json#L54-L82).

## What the editor actually implements

**Schemas and forms.** Individual sections select a document slice, reuse a Zod schema, and write through a common draft updater. They are explicitly authored forms, not a universal schema-to-form generator. The basics listener persists changes independently of submission; displaying validation errors is not itself a server write barrier. A separate writable-data parser validates strict input before accepting tolerant canonical read normalization. KXM should reuse this separation while retaining its own JSON Schema/Ajv contract and explicit migration rules. [Form wiring](https://github.com/kontextmind/reactive-resume/blob/fd3494ccac6ef4c47d01614a8a5dcdea08df85eb/apps/web/src/routes/builder/$resumeId/-sidebar/left/sections/basics.tsx#L21-L79), [write validation](https://github.com/kontextmind/reactive-resume/blob/fd3494ccac6ef4c47d01614a8a5dcdea08df85eb/packages/schema/src/resume/write.ts#L6-L35).

**Autosave and conflicting edits.** The in-memory draft runtime serializes saves, retains the newest queued full document, exposes saving/saved/error, and restores pending data on failure. It avoids replacing current content with an older response. However, the ordinary save calls `resume.update` without a base revision; the service locks the row but performs a full replacement without checking what version the editor read. Two editors can therefore overwrite one another sequentially. The separate JSON Patch path does check optional `expectedUpdatedAt` under `SELECT FOR UPDATE`, validates patch pointers and resulting data, and checkpoints within the transaction. Adopt the queue, but make revision checking mandatory for KXM edits. [Draft save loop](https://github.com/kontextmind/reactive-resume/blob/fd3494ccac6ef4c47d01614a8a5dcdea08df85eb/apps/web/src/features/resume/builder/draft.ts#L179-L242), [ordinary update](https://github.com/kontextmind/reactive-resume/blob/fd3494ccac6ef4c47d01614a8a5dcdea08df85eb/packages/api/src/features/resume/service.ts#L623-L670), [guarded patches](https://github.com/kontextmind/reactive-resume/blob/fd3494ccac6ef4c47d01614a8a5dcdea08df85eb/packages/api/src/features/resume/service.ts#L114-L193).

Route transitions can await the final save, block on error, and retain the draft after a ten-second wait. Unload cannot await completion; this is not an offline durable journal. Existing tests specifically exercise queued saves, stalled navigation, and failed drafts; they are useful acceptance examples, not tests run by this audit. [Navigation boundary](https://github.com/kontextmind/reactive-resume/blob/fd3494ccac6ef4c47d01614a8a5dcdea08df85eb/apps/web/src/features/resume/builder/draft.ts#L673-L729).

**History and publishing.** Server snapshots retain only thirty versions; ordinary saves checkpoint at most every two minutes and snapshot failures merely log. Restore copies historical content into the current document. The database has one current JSON document, `isPublic`, and `isLocked`, plus version rows: public visibility is not a separately approved, immutable published revision. Even the parser's variable named `publishedInputSchema` concerns JSON Schema publication, not document approval. None of these mechanisms should substitute for KXM evidence retention or independent gates. [Snapshot policy](https://github.com/kontextmind/reactive-resume/blob/fd3494ccac6ef4c47d01614a8a5dcdea08df85eb/packages/api/src/features/resume/service.ts#L64-L110), [restore implementation](https://github.com/kontextmind/reactive-resume/blob/fd3494ccac6ef4c47d01614a8a5dcdea08df85eb/packages/api/src/features/resume/service.ts#L415-L457), [document/version storage](https://github.com/kontextmind/reactive-resume/blob/fd3494ccac6ef4c47d01614a8a5dcdea08df85eb/packages/db/src/schema/resume.ts#L7-L68).

**Updates and reconnect.** PostgreSQL notifications carry document/user identity and mutation metadata; subscribers filter both identities, then the browser refetches canonical content. This is invalidation, not a replayable event log. The browser preserves dirty local content and defers external replacement while a field is focused. A concrete source defect limits reuse: the retry timer increments `_retryNonce`, but that value is absent from the subscription effect dependencies, so that state update alone does not restart the effect. [Notification implementation](https://github.com/kontextmind/reactive-resume/blob/fd3494ccac6ef4c47d01614a8a5dcdea08df85eb/packages/api/src/features/resume/events.ts#L39-L78), [subscription and remote edits](https://github.com/kontextmind/reactive-resume/blob/fd3494ccac6ef4c47d01614a8a5dcdea08df85eb/apps/web/src/features/resume/builder/draft.ts#L591-L670).

**Preview, export, access.** Rendering rejects stale asynchronous results by request identity and keeps the last valid preview after failure. Export shares the PDF generation entry point and centralizes JSON/Markdown/DOCX/PDF/print behavior. That supports coherent representations, not proof that a workflow ran. Public read policy hides private documents with NOT_FOUND and strips owner title/notes; mutation queries enforce owner identity. This owner/public model is narrower than KXM project/run capabilities and independent approvals. [Preview lifecycle](https://github.com/kontextmind/reactive-resume/blob/fd3494ccac6ef4c47d01614a8a5dcdea08df85eb/apps/web/src/features/resume/preview/preview.browser.tsx#L112-L154), [shared export](https://github.com/kontextmind/reactive-resume/blob/fd3494ccac6ef4c47d01614a8a5dcdea08df85eb/apps/web/src/features/resume/export/use-resume-export.ts#L48-L124), [read redaction policy](https://github.com/kontextmind/reactive-resume/blob/fd3494ccac6ef4c47d01614a8a5dcdea08df85eb/packages/api/src/features/resume/access-policy.ts#L22-L66).

## Five concrete adaptations

1. **M0 — truthful, scoped editor commands; small/medium effort.** Land in `plugins/kxm/src/studio-layout.ts` and `test/core/studio-layout.test.ts`. Replace the current no-handler success response with unavailable/failure, require authenticated mutation wiring, and distinguish draft saved, validation passed, approval recorded, command accepted, and execution completed. The current endpoint checks its token only when configured and reports `executedAt` even without a mutation handler. Acceptance: absent handler never reports execution; expired/wrong-scope credentials fail; save failure preserves editable content; clicking a preview cannot dispatch a workflow. [Current Studio mutation seam](https://github.com/kontextmind/kxm/blob/02aaed31fd6160a78378c677ab27d4119f039621/plugins/kxm/src/studio-layout.ts#L345-L430).

2. **M1 + M7 — shared schema-backed authoring; medium effort.** Add proposed `plugins/kxm/src/studio/editor-model.ts`, retain `schemas/workflow.schema.json`, and adapt `plugins/kxm/src/project-config.ts`. Produce one canonical draft for forms, source view, and DAG; expose field and cross-resource diagnostics from KXM's existing validator. A small typed component registry can organize stage, agent, gate, and repository panels. Upstream's template registry is compiled imports with a default fallback, not sandboxed plugin loading; KXM must reject unsupported execution-affecting types explicitly. Acceptance: form/source round trips preserve semantics; dangling references and missing plan-hash requirements produce the same errors as CLI; unavailable modes remain visible with reasons. [KXM resource validation](https://github.com/kontextmind/kxm/blob/02aaed31fd6160a78378c677ab27d4119f039621/plugins/kxm/src/project-config.ts#L697-L727), [compiled template registry](https://github.com/kontextmind/reactive-resume/blob/fd3494ccac6ef4c47d01614a8a5dcdea08df85eb/packages/pdf/src/templates/index.ts#L1-L39).

3. **M6 + M7 — revisioned drafts and reviewable restore; medium/large effort.** Add proposed `plugins/kxm/src/studio/drafts.ts`, with persistence in `runtime-store.ts` and approval integration through existing lifecycle commands. Store project, base/content hash, author, and edit history separately from active definitions; require compare-and-swap on save. Restore creates another draft with a visible diff, never rewrites approval evidence. KXM already persists sequence-addressed events and pinned run plans, and skill promotion requires an independent decider, evidence, passing evaluations, and integrity verification. Acceptance: two-tab stale save conflicts without loss; restart recovers acknowledged drafts; restoring or editing cannot alter a pinned run or self-approve a skill. [Durable runtime records](https://github.com/kontextmind/kxm/blob/02aaed31fd6160a78378c677ab27d4119f039621/plugins/kxm/src/runtime-store.ts#L517-L549), [existing promotion safeguards](https://github.com/kontextmind/kxm/blob/02aaed31fd6160a78378c677ab27d4119f039621/plugins/kxm/src/skills.ts#L387-L418).

4. **M7, supporting M2/M3 — revision-labelled preview and reconnect; medium effort.** Extend `studio-layout.ts` and `hub.ts`; add proposed `studio/view-state.ts`. Keep the last valid DAG while deriving a replacement, clearly label its revision/staleness, and discard late render results. Reuse existing authenticated, project-scoped operations snapshot/SSE endpoints; add sequence-aware reconciliation with the durable store instead of copying transient notifications as execution history. Acceptance: disconnect, edit through another native harness, reconnect, and reconcile without hiding local changes; old renders never win; redacted exports identify their exact definition/run revision and distinguish planned from observed outcomes. [Existing operations stream](https://github.com/kontextmind/kxm/blob/02aaed31fd6160a78378c677ab27d4119f039621/plugins/kxm/src/hub.ts#L1395-L1427).

5. **M1 + M9 — ship editor modules through one installation; medium effort.** Extend `scripts/build-runtime.mjs`, root `package.json`, and existing `test/core/package-install.test.ts`; package Studio assets and schemas together, loading UI/export code only when requested. Keep TypeScript and the existing runtime storage. Upstream setup introduces PostgreSQL/auth and optional storage/Redis services; its example configuration is setup evidence, not verified dependency necessity for every route. Neither uv/Python nor Rust is justified by these editor patterns. Acceptance: packed consumer outside the checkout opens Studio, validates/exports a fixture, survives refresh, and shares the same runtime across native harness clients; CLI-only use needs no browser bundle initialization or additional service. Extend the actual pack/install smoke rather than proposing one as missing. [Upstream setup surface](https://github.com/kontextmind/reactive-resume/blob/fd3494ccac6ef4c47d01614a8a5dcdea08df85eb/.env.example#L16-L86), [existing consumer test](https://github.com/kontextmind/kxm/blob/02aaed31fd6160a78378c677ab27d4119f039621/test/core/package-install.test.ts#L43-L82).

## Compatibility and boundary

For a concrete Studio workflow, editing a stage's repository access should first change a draft and update validation. Saving acknowledges durable draft storage; requesting review binds the exact proposed hash. A reviewer decision is a separate authenticated operation. Starting a run then pins the approved definition. Changing the draft afterward updates neither that approval nor the running plan. This distinction should appear in labels and command results, rather than being inferred from a green save icon. A visual lock can prevent accidental editing, but cannot serve as evidence of independent review.

Privacy needs a similarly explicit representation boundary. Upstream exports JSON from the supplied document, while public reads redact only selected fields. KXM should define its own export projection that excludes tokens, private notes, raw sensitive tool output, and unauthorized repository details before serializing anything. Downloading a redacted review artifact must not publish a live project URL. Acceptance should compare identical fixtures through Studio, CLI, export, and reconnect paths, including a second project with similar identifiers, to detect accidental cross-project disclosure. Preserve the distinction between authored configuration, editor recovery data, immutable review evidence, and observed runtime events in both retention policy and UI history.

The fork's MIT license permits adaptation with its notice retained; dependency, font, and template assets require their own review before copying. Prefer original KXM implementations of the patterns, without importing resume assets, public-link publishing, or account/provider management. Native provider credentials stay in their harnesses; Studio sessions authorize KXM operations, not provider login or approval bypass. M4 preview work can reuse the view model; M5 memory and M8 messaging remain separate interfaces. This fork supplies no evidence for their retrieval or delivery guarantees.
