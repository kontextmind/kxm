# dsh-web: future KXM Studio reference

**Category:** DSH-specific web/desktop plugin ecosystem, task board, and remote-control interface. **Relevance:** high for future Studio interaction and extension management; limited as a directly reusable execution backend. **Disposition:** adapt selected contracts and UI patterns; defer the aggregate package, Electron distribution, and its scheduler. **Priority:** M0/M2/M3 control foundations before M7 Studio expansion.

## Evidence boundary

This independent review compares `kontextmind/dsh-web` **8f44fa4691efdfc4bf75b21b86722e8fb7419b9b** with current KXM **02aaed31fd6160a78378c677ab27d4119f039621**, not the earlier 5ff9f642 baseline. Exact source files were fetched through the pinned evidence helper; paths and hashes are recorded in `dsh-web-metadata.json` beside this batch's tree inventory. Source, selected tests, current KXM AGENTS, and the harness-strategy research were read. Nothing was installed or executed, and audited repository instructions were not adopted as operational authority.

## Architecture and current overlap

dsh-web is not a replacement agent engine. The aggregate package declares DSH `>=0.1.5-rc.1`, exports host/client plugin entry points, and mounts a family of packages through Cordis. Its shell dynamically imports children and isolates activation failures; this is availability isolation inside the host process, not a security sandbox. The client also isolates child failures, but deliberately mounts every child when active-row discovery fails. That fail-open behavior must not determine KXM tool or permission availability. [Aggregate contract](https://github.com/kontextmind/dsh-web/blob/8f44fa4691efdfc4bf75b21b86722e8fb7419b9b/packages/dsh-web-all/package.json#L1-L42), [host mounting](https://github.com/kontextmind/dsh-web/blob/8f44fa4691efdfc4bf75b21b86722e8fb7419b9b/packages/dsh-web-all/src/shell.ts#L227-L258), [client uncertainty handling](https://github.com/kontextmind/dsh-web/blob/8f44fa4691efdfc4bf75b21b86722e8fb7419b9b/packages/dsh-web-all/src/client/mount-children.ts#L68-L145).

Its task board is a durable front end to DSH's Typert session gateway: it creates or reuses sessions, sets permissions/models, queues prompts, polls the roster, and inspects history. The native DSH session engine owns inference, tools, conversation streams, and ordinary chat approvals. Board recurrence is another host scheduling loop; importing it would duplicate KXM Runtime ownership.

Current KXM already has a Studio layout server and an owner-checked durable run event store. The CLI currently wires `planProvider` only: it supplies neither `stateProvider` nor `onMutation`. The server still makes authentication conditional on a supplied token and reports success for allowed mutations without an executor. Those existing gaps block an expanded Studio; they are not fixed by borrowing a richer dashboard. [Current CLI wiring](https://github.com/kontextmind/kxm/blob/02aaed31fd6160a78378c677ab27d4119f039621/plugins/kxm/src/cli/tasks.ts#L286-L327), [Studio boundary](https://github.com/kontextmind/kxm/blob/02aaed31fd6160a78378c677ab27d4119f039621/plugins/kxm/src/studio-layout.ts#L345-L430), [durable event ownership and paging](https://github.com/kontextmind/kxm/blob/02aaed31fd6160a78378c677ab27d4119f039621/plugins/kxm/src/vnext-runtime-store.ts#L774-L808).

## Execution, identity, approval, and persistence findings

- **Session identity is explicit but continuation is weaker than KXM needs.** Launch validates a named workspace and preset when the registry is present; reuse requires opt-in, a settled prior execution, and an idle session in a known roster. Unknown/missing sessions cause a fresh conversation. Reuse itself does not compare the existing session's workspace/preset with changed card pins. KXM should distinguish “continue this exact session” from “start another run,” bind canonical project/worktree identity, and refuse an ambiguous continuation. [Launch validation](https://github.com/kontextmind/dsh-web/blob/8f44fa4691efdfc4bf75b21b86722e8fb7419b9b/packages/dsh-task-board/src/host-runner.ts#L207-L246), [reuse rule](https://github.com/kontextmind/dsh-web/blob/8f44fa4691efdfc4bf75b21b86722e8fb7419b9b/packages/dsh-task-board/src/core/session-reuse.ts#L8-L31).
- **Permission acknowledgment is stronger than model pinning.** `/permission` must return success before prompting, but failed `selectModel` logs a warning and proceeds with the default. This contradicts KXM's authenticated-route and no-silent-billing-fallback requirements. The board's above-default permission gate is useful interaction design, but its `confirm-permission` action is not proof of a protected KXM reviewer or per-tool approval. The protocol explicitly treats `initiator` as client-asserted; its action union has no execution-cancel command. [Pinning behavior](https://github.com/kontextmind/dsh-web/blob/8f44fa4691efdfc4bf75b21b86722e8fb7419b9b/packages/dsh-task-board/src/host-runner.ts#L250-L282), [confirmation gate](https://github.com/kontextmind/dsh-web/blob/8f44fa4691efdfc4bf75b21b86722e8fb7419b9b/packages/dsh-task-board/src/host-ledger.ts#L591-L619), [action and initiator contract](https://github.com/kontextmind/dsh-web/blob/8f44fa4691efdfc4bf75b21b86722e8fb7419b9b/packages/dsh-task-board/src/protocol.ts#L86-L107).
- **Turn completion is not task acceptance.** History inspection takes a snapshot cursor, pages backwards with limits, and stays pending on unavailable history. However, it identifies completion using the first `turn/end` after a timestamp and treats every non-error reason as succeeded. The generated prompt request ID is not the settlement correlation key. A missing session becomes “cancelled,” which does not establish absence of external effects. Preserve native turn/run identifiers and KXM verification evidence instead. [Inspection and settlement](https://github.com/kontextmind/dsh-web/blob/8f44fa4691efdfc4bf75b21b86722e8fb7419b9b/packages/dsh-task-board/src/host-runner.ts#L329-L392).
- **Host persistence is real.** The ledger fingerprints request IDs and persists successful mutations with their deduplication records; file commits use owner-only temporary files, fsync, and rename. This is more than browser-local task state, but no distributed or database transaction guarantee follows. State is modified before file commit; a failed write needs explicit reconciliation. KXM should retain its SQLite/event transaction boundary rather than introduce another authoritative JSON ledger. [Request deduplication](https://github.com/kontextmind/dsh-web/blob/8f44fa4691efdfc4bf75b21b86722e8fb7419b9b/packages/dsh-task-board/src/host-ledger.ts#L408-L430), [file commit](https://github.com/kontextmind/dsh-web/blob/8f44fa4691efdfc4bf75b21b86722e8fb7419b9b/packages/dsh-task-board/src/host-ledger.ts#L798-L823).

## Streaming and remote access

The board SSE endpoint sends small revision/scheduler/power notifications, not a token transcript or replay log. It sends an initial notification, heartbeats, and unsubscribes on disconnect; it has no event IDs or backpressure handling in this route. A separate shared utility uses Web Locks and BroadcastChannel to elect one stream owner across tabs, but the inspected task-board client still creates its own EventSource. Adopt the shared-connection idea without claiming that all current panels use it. [Board events](https://github.com/kontextmind/dsh-web/blob/8f44fa4691efdfc4bf75b21b86722e8fb7419b9b/packages/dsh-task-board/src/host-routes.ts#L182-L210), [cross-tab relay](https://github.com/kontextmind/dsh-web/blob/8f44fa4691efdfc4bf75b21b86722e8fb7419b9b/shared/client/sse-leader.ts#L68-L120), [board subscription](https://github.com/kontextmind/dsh-web/blob/8f44fa4691efdfc4bf75b21b86722e8fb7419b9b/packages/dsh-task-board/src/client/host-api.ts#L195-L223).

The remote channel deliberately gives paired devices broad host control, including settings/credentials, while reserving selected management paths for local access. After authentication, it proxies traffic as loopback, strips outer authority headers, and adds the host's inner credential. WebSocket authentication occurs at upgrade; this inspected proxy path does not subscribe to device revocation or continuously re-authorize an established stream. Do not interpret pairing revocation as proven immediate teardown. Older-cohort comments about DSH's `api/gate` hook are not proof of current SDK behavior. [Remote privilege model](https://github.com/kontextmind/dsh-web/blob/8f44fa4691efdfc4bf75b21b86722e8fb7419b9b/packages/dsh-remote-web-ui/src/remote-methods.ts#L1-L74), [upgrade authorization](https://github.com/kontextmind/dsh-web/blob/8f44fa4691efdfc4bf75b21b86722e8fb7419b9b/packages/dsh-remote-web-ui/src/remote-api.ts#L211-L254), [proxy transport and teardown](https://github.com/kontextmind/dsh-web/blob/8f44fa4691efdfc4bf75b21b86722e8fb7419b9b/packages/dsh-remote-web-ui/src/loopback-proxy.ts#L58-L175).

KXM's accepted A1 process hardening is already ahead of a simple socket-close/child-kill model: escalation survives direct-child close and unverified descendants remain explicit. Reuse that evidence in Studio rather than declaring “stopped” when a viewer disconnects. KXM's existing `deepseek` catalog entry is not an implemented DSH gateway adapter. [Current A1 runner](https://github.com/kontextmind/kxm/blob/02aaed31fd6160a78378c677ab27d4119f039621/plugins/kxm/src/vnext-oneshot-process.ts#L79-L126).

## Workshop code trust

The installer stages downloads, bounds individual files/counts, records hashes, and leaves presets in an inert library. Useful distinctions are downloaded, enabled, and changed-after-download. However, hashes are calculated from received bytes and stored beside them: they are provenance receipts, not publisher signatures. Replacement deletes the old directory before renaming the new one, so failure at the final rename is not a rollback-safe replacement. Preset verification even reports extra files separately while allowing `valid` when expected files match. KXM should require an independently pinned manifest and reject unexpected executable files. Its existing skill promotion already requires protected evaluations, a distinct promoter, evidence, and a content-integrity check. [Installer publication](https://github.com/kontextmind/dsh-web/blob/8f44fa4691efdfc4bf75b21b86722e8fb7419b9b/packages/dsh-market/src/core/installer.ts#L273-L340), [preset verification](https://github.com/kontextmind/dsh-web/blob/8f44fa4691efdfc4bf75b21b86722e8fb7419b9b/packages/dsh-preset-center/src/core/provenance.ts#L80-L118), [KXM promotion](https://github.com/kontextmind/kxm/blob/02aaed31fd6160a78378c677ab27d4119f039621/plugins/kxm/src/skills.ts#L386-L418).

M4 should reuse KXM's existing browser/session boundary; dsh-web's visual panels do not justify another browser service. M5 receives reference-aware handoff UX, not a replacement memory database. The task board's cron loop, full-control pairing, legacy DOM compatibility shims, skins/pets, and complete Electron host remain deferred. These proposals do not change milestone acceptance or producer admission.

## Setup, license, and compatibility costs

The inspected source root is a private pnpm workspace (`pnpm@11.24.0`); the installable aggregate is version 0.3.22. It depends on DSH's Cordis/Typert/workspace/session ecosystem rather than KXM's public API. The repository's desktop manifest bundles a separate Node runtime, DSH host, and web profile, with macOS/Windows build targets: this would be a substantial second runtime/distribution owner. Preserve one KXM installation and make any DSH attachment explicit and version-tested. Source metadata declares Apache-2.0 and the inspected root LICENSE contains Apache 2.0 terms; retained NOTICE/attribution and any separately licensed artwork/dependencies need component-level checking before redistribution. This audit establishes source compatibility requirements, not live npm availability or tested desktop portability. [Desktop runtime and license declaration](https://github.com/kontextmind/dsh-web/blob/8f44fa4691efdfc4bf75b21b86722e8fb7419b9b/desktop/package.json#L1-L24).

**Conclusion:** dsh-web is a strong source of operational UI patterns. KXM should retain its execution/evidence Runtime, finish the local Studio command boundary, then add recoverable live views and governed extension management. Adopting the whole DSH web stack would introduce competing session, scheduler, credential, and installation authorities.
