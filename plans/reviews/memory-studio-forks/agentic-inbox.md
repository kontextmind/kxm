# agentic-inbox → persistent coordinator inboxes and KXM Studio

## Decision and scope

**Category:** hosted email ingress/storage, AI drafting, and browser inbox. **Applicability:** high for persistent coordinator identity and Studio interaction patterns; medium for an optional Cloudflare transport; low as KXM's execution/approval engine. **Disposition:** adapt the mailbox/agent separation and UI; replace ingress/wake/send semantics with KXM-owned durable contracts. SMS is a future sibling transport, not a feature supplied by this fork.

Reviewed `kontextmind/agentic-inbox` **48039bb6785af34e592c2966f87cde2b255c4c80**, upstream `cloudflare/agentic-inbox`, against KXM **02aaed31fd6160a78378c677ab27d4119f039621**. Selected source was fetched from the complete pinned tree. No upstream installation/execution, sending, identity provisioning, provider calls, or central plan/source changes occurred. Findings concern implementation, not production delivery guarantees.

## Actual architecture and gaps

### Durable mailbox identity is useful; mailbox partitioning is not authorization

The Worker routes mailbox IDs to `MailboxDO` through `idFromName(mailboxId)`, after checking an R2 mailbox manifest. MailboxDO uses Drizzle over Durable Object SQLite; a separate `EmailAgent` object owns AI chat. This separation supports an address that survives a chat session. It does not implement a stable KXM coordinator identity, lease, or task relationship. The deployment binds MailboxDO, EmailAgent, EmailMCP, R2, Workers AI, and outbound email. There is no Cloudflare Workflows binding or SMS implementation in the inspected tree. [Mailbox routing](https://github.com/kontextmind/agentic-inbox/blob/48039bb6785af34e592c2966f87cde2b255c4c80/workers/lib/mailbox.ts#L21-L40), [deployment bindings](https://github.com/kontextmind/agentic-inbox/blob/48039bb6785af34e592c2966f87cde2b255c4c80/wrangler.jsonc#L19-L69)

Production HTTP routes validate Cloudflare Access JWT issuer/audience and fail if Access configuration is missing; development skips validation. Passing that shared policy grants all-mailbox access by design. MCP checks mailbox existence, not owner/project permissions. KXM needs an explicit owner/coordinator/project identity model before exposing multiple primary agents or phone numbers. A verified provider callback proves transport origin, not that an email's apparent sender can approve a KXM action. [Access boundary](https://github.com/kontextmind/agentic-inbox/blob/48039bb6785af34e592c2966f87cde2b255c4c80/workers/app.ts#L45-L100), [MCP mailbox check](https://github.com/kontextmind/agentic-inbox/blob/48039bb6785af34e592c2966f87cde2b255c4c80/workers/mcp/index.ts#L73-L92)

### Receiving, waking, and executing are separate transitions

Ingress parses the MIME bytes and chooses one mailbox from the parsed `To` header. Its event type carries only `raw/rawSize`, so the implementation does not bind routing to an authenticated envelope recipient. It assigns a fresh UUID each time, writes attachments to R2, persists the email, then starts an agent fetch with `waitUntil`. Message-ID is retained as metadata but is not unique in the schema/migrations. Consequently duplicate ingress can create multiple records/drafts, and the post-storage wake path has no explicit durable job/receipt/retry state. It catches rejected fetches but does not inspect a returned HTTP error. [Ingress implementation](https://github.com/kontextmind/agentic-inbox/blob/48039bb6785af34e592c2966f87cde2b255c4c80/workers/index.ts#L348-L409), [message schema](https://github.com/kontextmind/agentic-inbox/blob/48039bb6785af34e592c2966f87cde2b255c4c80/workers/db/schema.ts#L13-L44)

Threading uses References/In-Reply-To, with a recent-subject/sender heuristic when headers are absent. That is an email conversation grouping mechanism, not a task identity or authorization link. KXM already distinguishes peer-message delivery modes and queued/delivered/replied states, persists sender-scoped idempotency keys and consumer cursors, and binds workflow evidence to hub-owned context. Preserve those controls while adding durable external conversation records that do not expire merely because a worker went offline. [KXM message contract](https://github.com/kontextmind/kxm/blob/02aaed31fd6160a78378c677ab27d4119f039621/plugins/kxm/src/protocol.ts#L16-L97), [KXM deduplication/cursors](https://github.com/kontextmind/kxm/blob/02aaed31fd6160a78378c677ab27d4119f039621/plugins/kxm/src/store.ts#L25-L47)

### Draft-only chat does not mean every send path enforces approval

The built-in agent's tool set provides drafting and mailbox management, without send tools; chat uses streamed Workers AI Kimi output and auto-drafting uses a separate generation call. Auto-draft success is inferred from whether a draft tool was called, not from inspecting its success result, and the handler returns `draft_generated` even when its inline-text fallback produced no stored draft. KXM should carry a concrete draft ID/revision and failure outcome instead. [Agent generation](https://github.com/kontextmind/agentic-inbox/blob/48039bb6785af34e592c2966f87cde2b255c4c80/workers/agent/index.ts#L275-L292), [auto-draft result logic](https://github.com/kontextmind/agentic-inbox/blob/48039bb6785af34e592c2966f87cde2b255c4c80/workers/agent/index.ts#L473-L549)

MCP separately exposes `send_email`/`send_reply`: descriptions say to get confirmation, but schemas carry no approved draft hash, authorization receipt, or idempotency key. The reply helper also runs AI proofreading immediately before sending, potentially changing text after the operator's review. KXM must approve the final recipients, body, attachments, and sender identity, with any subsequent content change invalidating that approval. AI injection detection/proofreading can assist triage; it cannot grant permissions or prove sender intent. [MCP send path](https://github.com/kontextmind/agentic-inbox/blob/48039bb6785af34e592c2966f87cde2b255c4c80/workers/mcp/index.ts#L313-L372), [pre-send transformation](https://github.com/kontextmind/agentic-inbox/blob/48039bb6785af34e592c2966f87cde2b255c4c80/workers/lib/tools.ts#L419-L467), [KXM authority ceiling](https://github.com/kontextmind/kxm/blob/02aaed31fd6160a78378c677ab27d4119f039621/plugins/kxm/src/context.ts#L26-L40)

### “Sent” is stronger than the inspected evidence

The HTTP send route first inserts into Sent, then defers the provider call, logs failures, and returns HTTP 202 with `status:"sent"`. The composer treats this as success, deletes an edited draft, and displays “Email sent!”. MCP's helper instead awaits the provider before storing Sent, but still has a failure window between external acceptance and local persistence. The sender returns the provider's message ID, which these inspected caller paths do not preserve as their canonical delivery receipt. None demonstrates recipient delivery. [HTTP send ordering](https://github.com/kontextmind/agentic-inbox/blob/48039bb6785af34e592c2966f87cde2b255c4c80/workers/index.ts#L181-L211), [composer outcome](https://github.com/kontextmind/agentic-inbox/blob/48039bb6785af34e592c2966f87cde2b255c4c80/app/hooks/useComposeForm.ts#L235-L261), [provider response](https://github.com/kontextmind/agentic-inbox/blob/48039bb6785af34e592c2966f87cde2b255c4c80/workers/email-sender.ts#L40-L71)

## Proposed KXM model and concrete work

Use a stable **coordinator ID** independent of native harness sessions. Bind one or more channel identities to it: email address now, SMS number/provider identity only through a separately admitted adapter. Preserve `inboxId`, transport receipt ID, external conversation ID, message ID, draft revision, KXM task ID, and run ID as separate fields. One conversation can inform several tasks; a task can cite several conversations. A message may wake the coordinator under configured policy without authorizing execution or an outbound response.

Reuse that discipline, but never route arbitrary incoming email/SMS directly to its `passed` stage-signal path. Tool-policy checks provide another existing control to extend, not a substitute for effect-bound send authorization. ## Studio, storage, packaging, and verification limits

The UI delegates chat streaming to `useAgent`/`useAgentChat`, keyed by mailbox ID; it disables send while streaming and exposes stop. Mail lists separately poll every 30 seconds and invalidate React Query caches after mutations. The fork itself contains no explicit durable reconnect cursor contract for the complete mailbox/wake/send lifecycle. KXM already has authenticated operations snapshots/SSE; extend them rather than treating an SDK WebSocket reconnect as proof of completed work. [Chat interaction](https://github.com/kontextmind/agentic-inbox/blob/48039bb6785af34e592c2966f87cde2b255c4c80/app/components/AgentPanel.tsx#L304-L328), [KXM operator stream](https://github.com/kontextmind/kxm/blob/02aaed31fd6160a78378c677ab27d4119f039621/plugins/kxm/src/hub.ts#L1395-L1427)

Search is parameterized SQL `LIKE` over message fields with date/status/attachment filters, not semantic memory or indexed full-text retrieval. Mailbox deletion currently removes its R2 manifest and explicitly leaves DO data/attachment cleanup as a TODO. Preserve this distinction when designing “delete identity”, “archive conversation”, and “erase content”; dropping a routing address must not silently destroy KXM evidence or falsely claim full deletion. [Search implementation](https://github.com/kontextmind/agentic-inbox/blob/48039bb6785af34e592c2966f87cde2b255c4c80/workers/durableObject/index.ts#L652-L717), [mailbox deletion](https://github.com/kontextmind/agentic-inbox/blob/48039bb6785af34e592c2966f87cde2b255c4c80/workers/index.ts#L126-L140)

The package is a private TypeScript application, Apache-2.0, using Workers/Agents, React Router, Drizzle and Workers AI. Scripts cover build/deploy/typecheck; no test script or test tree was present. It is not a reusable local npm mail service. Optional Cloudflare ingress still requires separate account/domain/routing/Access/R2/email-service configuration; one KXM installation should expose setup/status without silently provisioning cloud resources. No Python/uv/Rust runtime is introduced by this app; porting cloud-bound code to Node requires transport/storage adapters, not a language rewrite. Keep native model authentication in KXM rather than replacing it with the fork's hard-coded Workers AI routes. [Package/license/dependencies](https://github.com/kontextmind/agentic-inbox/blob/48039bb6785af34e592c2966f87cde2b255c4c80/package.json#L1-L52)

**M0–M9 placement:** M0 truthful receipts and redaction; M1 admitted channel capabilities; M2 durable progress/reconnect; M3 waking/steering with exact native-session semantics; M4 safe message/attachment previews; M5 scoped conversation evidence; M6 independent execution/send gates; M7 primary Studio inbox; M8 explicit email/SMS identity setup; M9 package and provider-adapter acceptance. **Recommended first slice:** persistent coordinator identity plus a receive-only durable inbox and visible wake status. SMS provisioning and outbound sends require their own concrete implementation and acceptance evidence. No runtime tests or delivery experiments were performed.
