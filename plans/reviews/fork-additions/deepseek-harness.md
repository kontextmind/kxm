# DeepSeek Harness: native adapter candidate, not the existing `deepseek` CLI

**Category:** full agent harness and plugin platform. **Relevance:** high to native-harness interoperability. **Disposition:** optional, pinned integration; adapt protocol patterns, defer worker admission. **Priority:** identity/readiness correction first, then an ACP experiment. This is static source review only: no installation, authentication changes, source execution, or tests were run. The unified milestones and both streaming/runtime-language research notes were read; this report is a proposal, not an implementation tracker.

## What its executable interfaces actually provide

- **Headless:** `dsh --profile headless <task>` accepts positional text, creates a fresh session with `process.cwd()`, streams provider reasoning to stderr, prints final assistant text to stdout, and returns success only for a completed turn. This implementation supplies neither a JSON event stream nor exact-session resume. [Parser](https://github.com/kontextmind/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/bundle/headless/src/startup.ts#L31), [runner](https://github.com/kontextmind/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/bundle/headless/src/index.ts#L170)
- **ACP:** the automation bridge uses newline-delimited JSON-RPC over stdin/stdout; exposes new/list/resume/close, prompt, configuration and cancel; validates absolute cwd and rejects active, subagent, or wrong-workspace resumes. Updates derive from committed session messages/tool events, so they are meaningful incremental observations but not token-level streaming. Concurrent prompts in one session are rejected; cancellation exists, but live steering is not established. Resume does not replay previous updates. [Bridge](https://github.com/kontextmind/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/acp/acp/src/index.ts#L239), [transport](https://github.com/kontextmind/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/acp/acp/src/index.ts#L361), [prompt control](https://github.com/kontextmind/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/acp/acp/src/session.ts#L243), [update conversion](https://github.com/kontextmind/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/acp/acp/src/updates.ts#L16)
- **Plugins/services:** Cordis plugins declare injected services/configuration and `apply(ctx, config)`; lifecycle effects dispose resources. The MCP client already mounts external tools, making a thin KXM service connection more appropriate than importing KXM into DSH’s agent loop. ACP MCP declarations require absolute stdio executables and bind cwd per session. [Plugin lifecycle](https://github.com/kontextmind/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/mcp/mcp-client/src/index.ts#L140), [ACP MCP mounting](https://github.com/kontextmind/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/acp/acp/src/mcp.ts#L25)

## Five implementable improvements

1. **Separate identity from capability and admission — M1/M9, S–M.** Extend `plugins/kxm/src/harness.ts` and `init-guide-setup.ts` with a distinct DSH candidate, exact executable/package version, and independently recorded detected/authenticated/protocol-verified/admitted states. Do not alias `deepseek` or copy its argv. **Acceptance:** fixtures for a legacy executable, only `dsh`, wrong package/version, and missing credentials never admit the wrong runtime; setup performs no implicit model call or provider fallback.

2. **Add an ACP transport beside the one-shot path — M2, then M3, L.** Add `plugins/kxm/src/vnext-acp-producer.ts`, using `pi-producer.ts` as a session-ownership reference and extending the runtime event path. KXM’s current `oneshot-process.ts` collects output until exit and closes stdin, so it cannot host this duplex protocol unchanged. Preserve bounded decoding, redaction, cancellation escalation, and explicit termination uncertainty. Store native session ID plus KXM run/attempt/scope identity and a KXM replay cursor. **Acceptance:** mock peers fragment UTF-8/JSON lines, overflow limits, interleave sessions, disconnect, resume with wrong cwd, and cancel during prompt admission; events remain ordered and deduplicated, with no invented replay or steering capability. [Current process behavior](https://github.com/kontextmind/kxm/blob/5ff9f642e82d7a1e52aeab9245282d89560bb535/plugins/kxm/src/oneshot-process.ts#L120), [existing Pi session ownership](https://github.com/kontextmind/kxm/blob/5ff9f642e82d7a1e52aeab9245282d89560bb535/plugins/kxm/src/pi-producer.ts#L473)

3. **Ship one explicit KXM registration — M1/M6/M9, M.** Extend `init-guide-setup.ts`, `scripts/build-runtime.mjs`, and `test/core/package-install.test.ts` to generate an opt-in DSH MCP profile pointing at the installed KXM executable/bundle. Reuse `commands.ts` and `mcp-server.ts`, which already share schemas and enforce KXM tool policy; avoid a parallel tool catalog or KXM runtime per plugin. **Acceptance:** a packed KXM consumer connects from outside the checkout, unavailable KXM fails clearly, duplicate registrations are prevented, disposal leaves the shared supervisor healthy, and no package download occurs during a task. [Existing MCP dispatch](https://github.com/kontextmind/kxm/blob/5ff9f642e82d7a1e52aeab9245282d89560bb535/plugins/kxm/src/mcp-server.ts#L110), [existing installed-artifact test](https://github.com/kontextmind/kxm/blob/5ff9f642e82d7a1e52aeab9245282d89560bb535/test/core/package-install.test.ts#L43)

4. **Require native permission evidence — M0/M1/M8, M–L.** Extend `harness.ts`, `permission.ts`, and adapter conformance tests with reviewed DSH profile provenance, native-tool restrictions, and fail-closed ACP permission handling. ACP advertises no authentication methods and implements authentication as a no-op; that is not credential readiness. Its provider resolves native credential references, which should remain native. **Acceptance:** rejected/unknown/disconnected permission responses grant nothing; native file/shell tools cannot bypass the claimed boundary; unauthorized MCP commands fail; missing credentials neither prompt unexpectedly nor trigger paid fallback. A producer stop reason remains separate from independent KXM gate acceptance. [ACP auth](https://github.com/kontextmind/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/acp/acp/src/index.ts#L175), [credential resolution](https://github.com/kontextmind/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/llm/llm-deepseek/src/index.ts#L447)

5. **Project governed skills into a native catalog — M6, M.** Extend `plugins/kxm/src/skills.ts` with a versioned export/manifest consumed through an explicit DSH custom skill root. DSH discovers `.dsh/skills`, `.agents/skills`, custom and user roots; KXM already governs evaluation and promotion. Export only selected, promoted versions with provenance and compatibility metadata. **Acceptance:** collisions resolve deterministically; quarantined/rejected versions are absent; changed bodies invalidate hashes; skills never alter permissions. [DSH discovery](https://github.com/kontextmind/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/skill/skill-filesystem/src/index.ts#L245), [KXM governance](https://github.com/kontextmind/kxm/blob/5ff9f642e82d7a1e52aeab9245282d89560bb535/plugins/kxm/src/skills.ts#L1)

## Distribution, runtime and scope limits

Keep the shared integration in TypeScript/JavaScript: both root manifests specify Node `^22.19.0 || >=24.0.0`. KXM already exports core/runtime/client/extension/MCP. The Python SDK depends on a bundled DSH runtime package; it is another distribution route, not evidence that uv/Python should replace KXM’s service layer. No Rust source/manifests were found in the scoped file search. DSH’s native system component is **C/Node-API**, with Linux Landlock and POSIX flock; Windows has neither that launcher nor addon. Any optional native component needs explicit, pinned setup and platform witnesses, not task-time builds or compiler requirements. [KXM exports](https://github.com/kontextmind/kxm/blob/5ff9f642e82d7a1e52aeab9245282d89560bb535/package.json#L54), [Python manifest](https://github.com/kontextmind/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/python/sdk/pyproject.toml#L5), [native manifest](https://github.com/kontextmind/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/native/system/packages/entry/package.json#L1), [platform limits](https://github.com/kontextmind/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/native/system/docs/support-matrix.md#L1)

**M0–M9 conclusion:** prioritize M0 permission/truthfulness and M1 identity/setup, experiment with M2 observation before M3 resume/control, and use M6 skills/M9 installed compatibility proof. M4 browser, M5 recall, and M7 documents/UI should remain shared KXM services accessed through the adapter; duplicating DSH’s equivalents adds competing state. M8 contributes masked readiness and native credential boundaries. No milestone, worker admission, or gate is advanced by this audit.
