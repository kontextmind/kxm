# Work plan: session-sized units, 2026-09-04

Every unit below is designed to run in a **fresh context session under 200k
tokens**. Units are ordered. Each one says exactly what to read, what to
change, the gate that proves it, and what to write back so the next session
does not have to rediscover it. Source reviews:
[part 1](2026-09-04-plan-review.md) and [part 2](2026-09-04-plan-review-part2.md).
Owner decisions that shaped this plan: [decisions](2026-09-04-decisions.md).
Where a unit and a decision disagree, the decision wins.

## Session protocol (every unit)

1. Read `AGENTS.md`, then this file's unit section, then the decisions the
   unit cites, then only the files the unit lists. Do not read the full
   reviews; the unit carries what it needs.
2. Run `git status` and `git log --oneline -5` first. `main` is protected: work
   on a branch named after the unit, open a PR that says `Closes #<slice>`.
3. Budget: reading is capped at about 1,500 source lines per unit and the diff
   at about 600 lines. If a unit is blowing past that, stop, split it, and
   record the split in the work log below.
4. Gate before push: `npm run verify`, then `npm run check:generated`.
5. **Write back** before ending: append a five-line entry to
   `.kxm/assets/reviews/2026-09-04-work-log.md` (unit id, what landed, PR,
   what surprised you, what the next unit should know). The work log and the
   PR are Git, which is the harness-agnostic memory until unit E5b lands.
6. Never "upgrade" scope. If a finding turns out wrong, say so in the log and
   move on. Breaking changes are fixed in tree; never add an alias (D3).

Token estimates are rough: reading 1,000 lines of TypeScript is about 15k
tokens; a full `npm test` transcript is 5k to 20k; writing 500 lines is about
10k plus retries.

## MVP gate (D1)

On a fresh machine with Pi, Claude CLI, and Codex CLI installed and logged
in: `npm install`, `kxm init`, then `kxm run quick "prompt"` completes with the
planner and reviewer roles dispatched through Claude and Codex and the
implementer through Pi on Grok or GLM. Every attempt leaves a routing record
with harness, provider, model, tokens, latency, and cost basis.
`kxm routing report` ranks routes by quality then cost. `kxm improve report`
shows recurrence, cost, and pass rate per step and emits a candidate.
`kxm dash` and the session brief show the run and its spend. A logged-out
harness fails closed at assignment.

## D2: engine, run loop and transitions

**Goal.** A run advances `created` to `preparing` to `running` through steps
to `completed` or `failed`, every transition an event.

**Read.** D1's module, `vnext-runtime-store.ts` 360 to 430, `vnext-runtime.ts`
180 to 320 and 380 to 425, `docs/vnext/lifecycles.md` step attempt section.

**Do.** `vnext-engine.ts`: step attempt creation, assignment creation (one
per step in 3a), attempt settle with an outcome key, transition selection
with budget checks, run terminal. Every change is an appended event with a
`schema` column (`kxm.run-event.v1`) in one transaction with the projection
update. Producers are an interface; this unit ships only a driver-simulated
producer. Caller-authored replies are rejected. The engine issues
`KXM_ATTEMPT_TOKEN` per attempt (consumed by D6). The loop is run-scoped:
N runs advance concurrently up to the project's `maxConcurrentRuns`, and
runs in different projects never contend.

**Gate.** A model-free test walks `quick.yaml` end to end; a back-edge past
`maxTransitions` fails the run; a caller-authored reply is rejected; the
projection rebuilt from events equals the incremental one.

## D3: engine, gate registry and evidence

**Goal.** `kind: gate` steps run a real command; evidence is attempt-bound.
Decision D5 (expect parameter).

**Read.** D2's module, `vnext-config.ts` `BUILTIN_GATES` and
`registeredGates` (about 60 lines), `cli.ts` `gate validate` handler.

**Do.** A non-legacy gate registry `.kxm/gates.yaml` with id, argv, timeout,
validated at load and read by the engine. `test` maps to `npm test` by
default. The engine spawns the argv; with `expect: pass` exit zero is

**Gate.** Tests with a fake argv for pass, fail, timeout, and both `expect`
modes; evidence from a prior attempt does not satisfy a new attempt.
